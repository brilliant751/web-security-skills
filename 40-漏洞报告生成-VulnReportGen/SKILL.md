# 漏洞报告生成 (vuln-report-generate)

把已复现的漏洞整理成可直接提交 SRC 平台的报告时使用。Use when 用户提到 生成漏洞报告、写漏洞报告、补天报告、漏洞盒子报告、SRC 提交、报告初稿、漏洞报告模板、危害等级判定、复现步骤整理、报告被打回返工 时加载。

## 何时使用

- 漏洞已经人工复现、证据已经拿到，需要整理成一份平台能收的报告时
- 用户说「生成报告」「写漏洞报告」「按补天/漏洞盒子的格式整理」时
- 报告被平台打回（无法复现、危害不足、证据缺失、疑似 AI 生成），需要按原因返工时
- 本条的输入是**已确认的事实**：只整理，不重新验证、不补充没有提供的内容；缺截图的地方留标注，由人工补

| 文件 | 用途 |

## 上手顺序

1. 先读主手册的「报告九段结构」，确认这次的漏洞该按哪九段写
2. 按「逐段写法」对齐每段的必填内容与常见退单点，不确定的地方回查原始证据，不靠推测补齐
3. 写复现步骤前先看「验到什么程度就算够」那张表——报告里多写一步越界动作，等于自己交代违规
4. 交付前跑一遍「提交前自检清单」；截图、录屏、原始请求包这些需要人工提供的部分，按统一标注留位置，不当成已完成
